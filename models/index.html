Families of models

This page provides theoretical and methodological background for the families of models implemented in this ecosystem. For hands-on, runnable code with output and interpretation, see the Examples.

Stochastic Actor-Oriented Models (SAOMs)

Stochastic Actor-Oriented Models, introduced by Snijders [1], model the co-evolution of networks and behavior over time. The core idea is that actors make sequential, myopic decisions to change their outgoing ties or behavior, guided by an objective function that encodes preferences for particular local network configurations.

The model distinguishes three components: a rate function governing how often actors get opportunities to change, an objective function determining which changes are attractive, and a behavior function when co-evolving behavior is included. Estimation uses a Method of Moments procedure (Robbins-Monro stochastic approximation), matching simulated network statistics to observed ones across two or more time points [2].

SAOMs are particularly suited to panel data where the same network is observed at discrete time points and the researcher is interested in disentangling selection from influence processes.

Julia implementation: Siena.jl implements the Method of Moments estimator of this framework for one-mode, undirected and two-mode networks and co-evolving behaviour, with interactions, score-type tests and time-heterogeneity tests. Every effect it offers under an RSiena name is checked against RSiena. Maximum-likelihood and Bayesian estimation, multi-group data and RSiena’s other model types are not implemented; see current coverage.

Relational Event Models (REMs)

Relational Event Models, developed by Butts [3], analyze time-stamped sequences of interaction events between actors. Unlike panel-based models, REMs treat each individual event as a unit of analysis, modeling the instantaneous rate or probability that a specific dyad interacts at a given moment.

History-dependent statistics capture reciprocity, repetition and other network effects alongside exogenous covariates. Ordinal models condition on an event and model which dyad acts; timing models also use waiting-time exposure. Ordinal estimation can compare the observed event with a full or sampled risk set. Duration fitting requires a timing likelihood.

Event models apply to interaction sequences such as email exchanges and communication logs. The observation process determines whether only event order, elapsed times, or both can be analysed.

Julia implementations: REM.jl supports full or sampled ordinal risk sets; Revel.jl adds the literature's network effects, covariates, interactions and goodness-of-fit checks, for full or restricted risk sets and supported exponential timing models. An ordinal sequence does not supply elapsed durations. Exact timing requires interval-constant statistics; continuous-decay hazard integration is unavailable.

Exponential Random Graph Models (ERGMs)

Exponential Random Graph Models [4] specify a probability distribution over graphs of a given size, where the probability of observing a particular network is an exponential function of a vector of network statistics. The general form is:

P(Y = y) = (1/κ(θ)) exp(θ′ g(y))

where g(y) is a vector of sufficient statistics (e.g., number of edges, triangles, degree distributions), θ is the parameter vector, and κ(θ) is a normalizing constant that is typically intractable for all but the smallest networks.

Estimation relies on either Maximum Pseudolikelihood Estimation (MPLE) [5], which multiplies each dyad’s conditional probability given the remaining dyads, or Monte Carlo Maximum Likelihood Estimation (MCMLE) [6], which uses MCMC sampling to approximate the ratio of normalizing constants. Goodness of fit is assessed by simulating networks from the fitted model and comparing their properties to the observed network [7].

The ERGM framework has been extended in several directions: temporal ERGMs (TERGMs) for longitudinal network data [8], valued ERGMs for count or rank data [9], ego-centric ERGMs for inference from sampled ego-network data [10], and multilayer ERGMs for networks with multiple relation types [11].

Implemented in: ERGM.jl and extensions (TERGM.jl, ERGMCount.jl, ERGMEgo.jl, ERGMMulti.jl, ERGMRank.jl, ERGMUserterms.jl)

Implementation scope differs across these packages. ERGM.jl, ERGMCount.jl and ERGMMulti.jl follow R’s default: the MPLE, which is then the exact MLE, when no term is dyad-dependent, and MCMLE otherwise. Rank models are fitted by rank MCMC-MLE, with a swap pseudo-likelihood as an option. TERGM.jl’s default fits the conditional MLE by MCMC when a term is dyad-dependent and the conditional MPLE, which is then the exact conditional MLE, otherwise (R’s tergm() has no default and requires estimate=); EGMME is not implemented. A method family described here does not imply that every variant is implemented. Consult estimator capabilities before selecting a model.
